# Scout Database Schema
### Designing the Memory of Scout

> "The database should remember everything that makes Scout smarter."

---

# Philosophy

Scout has two kinds of intelligence.

## Global Intelligence

Knowledge shared by every user.

Examples

- Opportunities
- Organizations
- Discovery Logs
- Trust Scores

---

## Personal Intelligence

Knowledge unique to each user.

Examples

- Profile
- Preferences
- Applications
- Bookmarks
- Activity
- Recommendations

These two worlds should remain independent.

# TTL Strategy

Temporary collections

```
recommendations

crawler_jobs

system_logs
```

can automatically expire.

Permanent collections

```
users

profiles

organizations

opportunities

applications

bookmarks
```

should never expire.

# Engineering Principles

1.

Separate authentication from user intelligence.

---

2.

Separate organizations from opportunities.

---

3.

Never duplicate data unnecessarily.

---

4.

Prefer references over deeply nested documents.

---

5.

Never delete important data.

Archive instead.

---

6.

Design for AI enrichment.

Every document should be capable of becoming richer over time.

---

# North Star

Scout's database should not merely store information.

It should become a continuously evolving knowledge graph of opportunities, organizations, and user aspirations.
