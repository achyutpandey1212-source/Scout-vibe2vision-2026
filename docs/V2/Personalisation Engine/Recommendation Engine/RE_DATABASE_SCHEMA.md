# RE_DATABASE_SCHEMA.md

> **Version:** Scout MVP V2
>
> This document defines every database object required by the Recommendation Engine.
>
> The Recommendation Engine never modifies Opportunity data.
>
> It consumes Opportunity documents and produces **Recommendation Packs**.
>
> The schema is intentionally versioned so future recommendation algorithms can evolve without breaking historical data.

---

# 1. Philosophy

Scout separates data into three layers.

```
Discovery Engine

↓

Opportunity Collection

↓

Recommendation Engine

↓

Recommendation Pack

↓

Dashboard
```

The dashboard **never recomputes recommendations.**

It only renders the Recommendation Pack.

---

# 24. Design Decisions

### Recommendation Packs are immutable

A generated pack is never edited.

If recommendations change

↓

Generate a new pack.

---

### Opportunities remain the source of truth

Recommendation Packs only reference opportunities.

No duplicated opportunity data.

---

### Dashboard is read-only

The frontend performs zero recommendation logic.

Everything is prepared server-side.

---

### Version everything

Store

- Recommendation Version
- Prompt Version
- Model
- Provider
- Profile Hash

This makes debugging and future experimentation straightforward.

---

# 25. Guiding Principle

The database should reflect Scout's architecture:

- **Discovery** owns opportunities.
- **Recommendation Engine** owns personalized recommendation packs.
- **Dashboard** only renders prepared results.

This clear separation keeps the system scalable, testable, and easy to evolve as Scout grows from an MVP into a production platform.
